## 二、根因分析（七个漏洞）

### 漏洞 1：moving 状态无超时 → 小舟永久卡死（"送饭菜卡住"的直接原因）

**原理**：状态机里只有 `idle` / `waiting_model` 状态的角色会触发重新决策。厨房做饭有两个使用位 `(13,3)`、`(13,4)`，被占用时寻路逻辑的原话是"被占用时保留目标并等待"——而 `player.tick` 的 moving 分支中路径不通就 `return`，**没有任何超时**。小舟决定做饭 → 厨房位被长期占用 → 永远等在原地 → 不吃不睡不决策，心情掉到 0。

**修复**（`engine/player.py`）：新增停滞计数 `_stall_ticks`——moving 中位置连续无进展时递增；**6 刻（1 小时）时重新挑一个当前空闲的使用位**（只有真的换到别的点位才重置计数，防止全忙时空转）；**12 刻（2 小时）后彻底放弃行动**，释放使用位、回到 idle 重新决策，并写入记忆"等太久先算了"。同理给 `waiting_activity`（等床伴就位）加了 12 刻超时。

### 漏洞 2：借款模板 KeyError → 小鹿永久卡在"待收治"

**原理**：`brain.py` 的 `LOAN_TEMPLATE` 里有 `{cap:.0f}` 占位符，但 `format()` 调用没传 `cap` → 每次构造提示词直接抛 `KeyError` → 整个 `_drain_loans` 异步任务无声崩溃（异常只在 GC 时打印，服务器日志看不到）→ 兜底的"拒绝收治"逻辑永远执行不到 → 病人 `awaiting_admission=True` 永久挂起，**被排除出所有决策**（决策筛选条件里排除了待收治者）。小鹿从第 2 天 07:30 起被冻结 1.5 天，hp 13、饱食 0 纹丝不动。

**修复**（`engine/brain.py` + `engine/simulation.py`）：补传 `cap=min(need, lender_cash)`；借款循环每个请求单独 try/except（单笔失败按"借 0"处理，不再杀死整个任务）；任务加 `add_done_callback`，再崩会留下事件日志。已用复现脚本验证：全部借款失败时也能正确落到"拒绝收治"。

### 漏洞 3：数值型 LLM 调用被思考阶段截断 → 好感度冻结

**原理**：周期好感判断（`max_tokens=8`）、互动好感结算（10）、借款（10）这类"只输出一个数字"的调用，对推理型模型（DeepSeek-V4 / MiniMax-M3.1 / GLM 系）来说是灾难：模型先输出思考过程，**8~10 个 token 的额度在思考阶段就耗尽，最终 `content` 为空** → `_extract_text` 抛"模型暂未输出最终回答" → 调用方降级为 0。回放中 368 次周期好感调用 365 次这样失败，互动结算 33 次全军覆没——好感度当然纹丝不动，还白白烧掉 400 次 API 调用。

**修复**：
- `engine/llm.py`：`content` 为空时回退读取 `reasoning_content`（DeepSeek 风格）的**末尾 600 字**——数值结论通常就在末尾；
- `engine/brain.py`：新增 `parse_last_int()`（取文本最后一个整数）+ `_strip_think()`（剥掉完整 think 段），三处数值调用统一改为"取末尾整数并钳制到合法区间"；`max_tokens` 提高到 512。钳制保证即使从思考文本里误取数字，影响也被限制在 ±1 / ±5 / 0..cap 内。

### 漏洞 4：`parse_decision` 白名单漏字段 → 电脑搜索词永远丢失

**原理**：`Decision` 模型里有 `query`、`symbol` 字段，但 `parse_decision` 提取额外字段的元组白名单里**没有它们**——模型明明输出了 `"query":"岗位时薪"`，解析时被静默丢弃，`search_knowledge` 收到空字符串，永远只返回目录页。小鹿 14 次、小野多次搜索全部空手而归；这也是"查不到工作信息 → 不去上班 → 破产"链条的一环。

**修复**（`engine/brain.py` + `engine/resident_tools.py`）：白名单补上 `query`、`symbol`；超长字段（query 60 / title 120 / content 20000 / memory_note 300）**截断而不是整条决策被 pydantic 拒绝**；`search_knowledge` 分类匹配从"全等"放宽为"包含"（"岗位时薪"、"挣钱"都能命中岗位目录），并新增"赚钱/挣钱/诊所"等关键词。

### 漏洞 5：电脑查询结果无处落地 → 查了等于白查（追加需求）

**原理**：搜索/读取结果只存进 `computer_feedback`，它只在"下一次决策仍坐在电脑前"时可见，之后彻底消失。角色查到岗位时薪 → 站起来 → 立刻忘光。这正是您指出的问题。

**修复**（`engine/resident_tools.py` + `engine/player.py`）：新增 `remember_computer_use()`——电脑活动结算时自动把结果写入记忆流：`search/read/list` 记"我用电脑查到：…"（截断 240 字，重要度 5），`create` 记"我在电脑里新建了记录《标题》"（重要度 4）。同时提示词明确告知"search/read 的查询结果会自动存入记忆，不必反复查询"。原有的 `memory_note` 机制（下一次决策附带感想）保持不变，两者互补。

### 漏洞 6：经济系统单向失血

三个因素叠加导致全员破产：

1. **急救费 1200 元**：初始金 100、最高时薪 36，一次昏倒等于 33 小时工时，还会通过借款抽干全屋现金（回放中小鹿的 1160 元借款需求直接压垮经济）；
2. **工作不可见**：`work` 属于"到场才可见"的场所项目，在家时菜单里根本看不到，模型不知道去哪挣钱——197 个决策 0 次工作；
3. **规则引擎优先级缺陷**（无 API 兜底模式）：饿了→做饭（4 元）→没钱→"抵达后钱不够"→idle→又决定做饭……死循环直到饿死；深夜饭店（10-22 点营业）关门后角色还会站在门口反复决策"下馆子"被静默拒绝。

**修复**：
- `mechanics.py`：**急救费 1200→300**（约 2.5 天工资或 3 人合借可承受）；
- 拒收语义改为**"先救人后收费"**：凑不齐钱时诊所做最低处置（生命 25 / 饱食 30 / 心情 20 保底），杜绝"凑不齐钱 = 必死"；
- 菜单：在家时的"小镇日常"区固定显示一行 `visit` 引导（"缺钱可去事务所O（上班）、田园F（劳作）挣钱……"），保留"到场才见项目"的探索设计，但把出路摆在眼前；现金 <40 时决策上下文额外提示"现金紧张：可前往 O/F 上班"；
- `decide_rule` 重构优先级：**能吃上饭就先吃饭**（饥饿是掉血主因，先止伤再治病）→ 饿但没钱时白天去工作、深夜睡觉节能 → 深夜饭店关门回家而不是原地循环。

### 漏洞 7：好感队列被周期轮询挤占

`_drain_affinity` 是串行队列，每刻塞 1 条周期好感请求，真实的对话/协同结算请求排在其后，而周期请求又大多因漏洞 3 失败重试，拖慢乃至淹没互动结算。**修复**：出队时优先取第一条非 periodic 请求，周期判断永远让位给真实互动。

## 三、追加需求的实现

**卧室区分命名**：`world.py` 新增 `BEDROOM_OWNERS` 注册表与 `bedroom_index_at()`，`zone_of()` 在卧室区返回"**小舟的卧室**"这类带主人名的区域名（无主时回落"卧室"）。`Simulation.refresh_bedroom_names()` 在每帧、每 tick、身份确定、玩家移除时刷新。角色的位置感知、记忆（"我在小舟的卧室"）、前端 `home` 字段全部自动生效。

**电脑使用体验**：合并漏洞 4、5 的修复——搜索词能传到了、模糊匹配能命中了、查到的内容自动进记忆了。另外离桌直接操作电脑从"静默无效"改为给出明确反馈（不泄露文件内容）。

## 四、平衡调整汇总

| 参数 | 旧值 | 新值 | 理由 |
|---|---|---|---|
| 急救费 `hospital_cost` | 1200 | **300** | 初始金 100 + 时薪 36 之下，1200 一次即全屋破产 |
| 心情基础消耗 `base_mood_drain` | 1.0/刻 | **0.6/刻** | 旧值 144/天，普通活动节奏根本补不回来，全员抑郁→掉血→住院连锁 |
| 饭菜保质期 `meal_shelf_life_ticks` | 20 刻 | **36 刻** | 3 小时就过期制造了大量"快过期"焦虑式送饭/扔饭循环 |
| 拒收处置 | 无（硬扛） | **生命25/饱食30/心情20 保底** | 先救人后收费 |
| moving 停滞 | 无超时 | **6 刻换位 / 12 刻放弃** | 见漏洞 1 |

> 注意：这些是 `DEFAULT_RULES` 默认值，**新开的实验生效**；已有存档中保存的机制参数会覆盖默认值，需要在新一轮实验的机制面板里确认或重开。

## 五、验证结果

1. **单元测试**：278 项全部通过（`python3 -m pytest tests/`）。其中 13 项按新契约更新了断言（数值从机制面板读取而非硬编码，reasoning_content 兜底视为成功等）。
2. **借款复现**：模拟推理模型全失败场景，借款任务正常收尾（拒收+保底），不再冻结病人；规则模式凑得齐时正常收治。
3. **死锁复现**：人工构造"厨房使用位被占"场景，角色 13 刻内正确放弃行动回到决策。
4. **3 天 / 5 天离线规则模拟**（4 人，seed=42）：修复前 3 人死亡、1 人卡死；修复后**全员存活**，5 天完成 18 次工作（约 648 元工资流入），好感度从 50 发展到 67~79，无人卡死、无 awaiting/hospitalized 挂起。规则人格是"降智"运行，LLM 模式的规划能力会显著好于这个下限。

## 六、遗留观察点（本轮未改，供下轮实验关注）

1. **决策节奏**：任一角色 `deciding/waiting_model` 时整个世界冻结（设计如此，防止思考期间掉血），推理模型单次 90 秒超时会让一天跑得很慢。若下轮仍觉缓慢，可把 `decision_timeout` 从 90 降到 45~60，或为不同调用分级超时。
2. **通勤成本**：步行 0.6 饱食/格 + 0.65 精力/格，镇上远处场所单程 20+ 格的消耗不低。目前经济下可承受，若下轮出现"赚的不够路上吃"可微调 `walk_satiety_per_tile`。
3. **回放文件体积**：每帧内嵌完整 checkpoint，3 天实验产生 950 MB。若磁盘吃紧，可改为每 N 帧存一次 checkpoint。
