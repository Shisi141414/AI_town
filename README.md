# 🏘️ AI 小镇

一个基于大语言模型的多智能体生活模拟游戏：几位 AI 居民合租一个大平层，默认 3 人，每人可绑定不同的 LLM。游戏参与者只有这些合租居民，室外是他们开展活动的地图，没有其他 NPC 或人类玩家角色。他们开局**自己给自己起名字、选择性别和颜色**，然后在同一份提示词下，凭借各自的记忆、数值状态和人际关系自主生活——做饭、打游戏、上班、看电影、买花送礼、交朋友、恋爱，也可能吵架搞破坏。

## 🚀 快速开始指南（5 分钟上手）

**你需要**：一台电脑 + 一个浏览器 + （可选）一个大模型的 API Key。不配 Key 也能玩（内置规则模式），配了才有人格。

**第 1 步 · 安装 Python**（已有可跳过）

打开 [python.org/downloads](https://www.python.org/downloads/)，下载最新版安装包，双击运行。安装界面**务必勾选 “Add Python to PATH”**（最底部的复选框），然后点 Install Now。

装好后验证：按 `Win + R`，输入 `cmd` 回车，在黑窗口里输入 `python --version`，显示版本号（如 `Python 3.12.x`）即成功。

**第 2 步 · 下载本项目**

点击本页面绿色的 **`<> Code`** 按钮 → **Download ZIP**，解压到任意文件夹（例如 `D:\AI_town`）。

**第 3 步 · 安装依赖**

打开刚才的命令行窗口（`Win + R` → `cmd`），输入下面两行，**每行输完按一次回车**，等待完成：

```
cd /d D:\AI_town
pip install -r requirements.txt
```

（第一行的路径换成你解压的位置；看到 `Successfully installed ...` 就装好了。）

**第 4 步 · 启动游戏**

在同一窗口输入：

```
python server.py
```

看到这样的提示就成功了：

```
========================================================
  AI Town  http://127.0.0.1:8300
========================================================
```

保持这个窗口开着（关掉窗口=关掉游戏）。

**第 5 步 · 打开游戏**

打开浏览器（Chrome / Edge 均可），地址栏输入 `127.0.0.1:8300` 回车。点 **「开始」** 即可看到 AI 居民开始生活。想重来一局就点「重置」。

**第 6 步 ·（推荐）接入大模型，让居民真正“活”起来**

1. 在页面右侧点 **「API / 模型」** → **新增档案**
2. 填三样：**Base URL**（服务商给的接口地址）、**API Key**（服务商给的密钥）、**格式**（OpenAI 或 Anthropic，看服务商文档）
3. 点 **「获取模型列表」** → 从拉出的列表里挑一个 → **测试** → **启用**
4. 到 **「玩家模型绑定」**，给每个居民挑一个模型（可以每人不同，观察不同“人格”）
5. 回到主界面点「开始」——现在居民会自己起名字、选形象、谈恋爱、吵架、深夜打游戏

> 💡 国内可用的低价/免费网关很多（硅基流动、智谱 BigModel、DeepSeek 官方等），注册后即可拿到 Key。页面右上角 **📖 指南** 有更详细的图文说明。
> ⚠️ 你的 Key 只保存在本机 `config.json`，本项目不会上传到任何地方。

**常见问题**

- 端口被占用（提示 `10048`）：上一次的服务还在运行。命令行输入 `taskkill /F /IM python.exe` 后重新 `python server.py`（会关闭所有 python 程序，介意的话改用 `netstat -ano | findstr 8300` 找到 PID 再 `taskkill /F /PID 那个数字`）。
- `pip` 不是内部命令：第 1 步没勾 “Add to PATH”，重新安装 Python 即可。
- 页面打不开：确认启动窗口还开着、地址是 `127.0.0.1:8300`（不要加 www）。
- 想完全重来：页面点「重置」；想彻底删除所有存档：关掉服务，删掉项目文件夹里的 `data` 文件夹。

**核心特点**

- 🎭 **开局身份自选**：每个居民的模型自己决定叫什么（小x 格式）、性别与颜色
- 🧠 **模型即人格**：5 个居民可各接一个模型（DeepSeek / GLM / Qwen / ERNIE / MiniMax…），同一提示词下观察行为差异
- 🏠🌆 **双场景世界**：室内合租之家（5 卧 / 客厅 / 厨房 / 餐厅 / 双卫 / 洗衣区 / 大阳台）+ 室外小镇（商店 / 公园 / 办公楼 / 电影院 / 健身房 / 医院 / 施工地 / 田地），两图独立比例尺，居民从大门出入
- 🤝 **协同增益社交**：一起打游戏/吃饭/工作有数值加成，好感度调制加成幅度——关系差一起做事反而互相拖累；每次互动后由模型自己决定好感增减（-5~+5）
- 💐 **物品与装饰**：去商店买鲜花/盆栽，布置自己的房间或公共区域（持续心情加成），或送给心上人
- 💰 **生存与经济闭环**：饱食/精力/心情/生命四维数值、生病送医、向室友借钱交急救费、住院计费、多股票市场（场所股价受居民消费影响）、饭菜保质期
- 🕸 **好感网络图**：实时可视化的居民关系网
- 📋 **模型列表获取**：填好 API 后一键拉取网关全部可用模型，点选即用
- ✏️ **可编辑统一提示词**：网页上直接改，下次决策生效
- 🛡️ **永不下线**：LLM 不可用时自动降级内置规则引擎；对白生成失败用内置文案兜底

### 设计说明

**同一提示词，人格涌现**：提示词不含任何人设，只有时间、数值、记忆、好感、活动菜单。个体差异来自经历的沉淀（斯坦福 Generative Agents 思想）。身份自选把这个思想推到开局——连名字都是模型自己选的。

**协同增益公式**：`倍率 = 人数增益 × 好感调制`。每多 1 人 +0.35 倍；好感 50 → ×1.0，100 → ×1.5，0 → ×0.5。关系不睦（倍率 <0.75）时正收益再打五折——「不如一个人做」。

**跨场景出行**：去另一场景的设施时，寻路分两段——先到本场景大门，切换场景坐标，再走到目的地。就像真实世界的「先下楼」。

**好感决定权交给模型**：互动结束后向该居民的模型提问「你对 TA 的好感变化多少」（-5~+5 的整数），规则只框边界不框方向。这让社交关系成为真正的涌现现象而非参数脚本。

## 像素场景与出行

室内为暖色俯视房间，采用薄墙、木地板和像素家具；室外为建筑、街道、绿地、水域组成的地图。点击地图中的居民或居民卡片可选中对应 AI，再在「室友的出行计划」查看和调整其行为。界面不提供额外的人类玩家角色。

| 方式 | 室外上限 | 每格额外饱食消耗 | 每格费用 |
|---|---:|---:|---:|
| 步行 | 3 格/tick | 0.18 | 0 |
| 骑行 | 6 格/tick | 0.25 | 0 |
| 汽车 | 道路上 12 格/tick | 0 | 0.15 |

汽车驾驶和搭乘期间不扣被动饱食消耗，其他基础生命/精力/心情规则保留；室内始终步行，汽车离开道路时停车并步行。全镇开局仅有 **1 辆共用汽车**，同时只能由一名居民使用；每位居民可以花 **1000 金钱**购买 **1 辆私家车**。车辆有停车位置，不能在远处直接取车。司机外可载 3 位室友，乘客在司机处于车位、距离两格以内时上车；离开道路或回家时自动下车。

模型提示词包含两张地图的活动、车辆位置、占用情况和购车价格。模型可附加 `travel_mode`，或选择 `buy_car`、`ride`、`stay_in_car`、`leave_car`。无 API 时仍使用原有规则降级，界面也可以干预居民的出行。

金钱、车辆、疾病等世界数值仍在当前服务进程内存在，重置或重启会重新开局。记忆现单独保存在本地数据库，默认居民按稳定入住槽位恢复，重置不会删除深层记忆。默认居民的 **API/模型绑定**按稳定入住槽位保留，旧 UUID 绑定按配置中的原入住顺序兼容。

### 平面布局与开局性别（2026-10-28）

室内按照参考平面图重排：左侧三间卧室、上下一间卧室，顶部厨房，中央餐厅，右侧客厅与阳台，下方两间卫浴。五间卧室均为 **6×4 格**，面积、形状和家具配置一致。门口仍在东侧，所有可行走区域相互连通。

诊所保留完整的 6×3 格范围，田地位于南侧两行，中间增加道路，避免田地覆盖诊所。模型开局只能自主选择「男」或「女」，性别显示在居民卡片并进入后续模型提示。首次提问明确给出男/女选项，不追加改答请求；非法值或规则模式使用默认男性。现有小人作为男性，女性使用同风格的长发、发夹与裙装像素形象。已有存档中的不支持值在读取时归为默认男性。


## 三级记忆与低概率事件

一级记忆收录活动、完整聊天、相遇、出行和生活事件；接近48条或10000字时，整理最旧的最多40条为10条二级记忆。二级接近24条或5000字时，将最旧的最多20条整理为5条三级记忆。较新的记录暂留原层，等待下一次整理。

**保留流程**：例如需要保留10条，模型先提名最想保留的10条，再从中随机抽8条；另从本次待整理的全部记忆中抽2条，排除已抽中的记录以确保最终10条不重复。模型提名但未抽中的记录仍可参加全池随机抽取。两部分记录分别标记权重0.8、0.2，也参与检索排序。模型缺失、超时或格式错误时，先按重要度补足候选，再执行同样的随机步骤，并标记为兜底，避免把规则结果冒充模型选择。

三级没有自动淘汰或再次压缩逻辑。数据库位于 `data/saves/<时间编号>/memories/`，与世界存档隔离。同一存档内三级记忆不自动遗忘，重置创建的新存档三个层级全部为空；继续旧档可以恢复原有记忆。保存整个存档目录即可保留世界和记忆，已加入忽略规则。决策只检索最多8条、2400字，聊天只检索最多4条、1200字；深层记忆按关键词检索，不会全部塞入上下文。设置页可分层查看、分页读取，事件页可筛选记忆整理记录。

随机事件使用独立随机源，每6刻检查：每位居民每日生病概率约2%，好感随机波动约4%（冷却会进一步降低实际发生率）。疾病轻/中/重症初始比例85%/13%/2%，持续18/36/60刻，生命额外消耗每刻0.02/0.06/0.12，少量消耗精力；每12刻有3%概率加重一级，但不延长原恢复时间。自然恢复或完成诊所治疗可清除疾病，生病后3天内不再触发新疾病。疾病本身不会让生命降到1以下，也不会把原本已经归零的生命恢复。好感波动为±1～2，单居民一天内最多一次，始终限制在0～100。居民卡片和模型提示中均显示健康状况，中/重症时规则模式会优先就诊。


## 开局、活动时长与过程回放

开局为第1天08:00，一刻仍为游戏内10分钟。模型可在行动JSON中填写 `duration_minutes`，例如 `{"action":"sleep","duration_minutes":480}` 或 `{"action":"game","duration_minutes":120}`。活动到达目的地后开始计时，时间内不再进行生活行动决策；未填写时沿用原默认时长。最短10分钟、最长24小时，向上取整到10分钟。突发急救、互动对象离开或手动更改出行等仍可中断活动。对话回合中的说话/离开属于互动回应，并非重新选择生活活动。

点击开始、继续或单步后自动录制至 `data/replays/`。档案保存地图、居民数值与身份、关系、活动剩余时间、车辆、事件与逐句聊天、记忆增删、执行中的路径/对话，以及模型请求和回答；不保存API密钥。暂停与继续使用同一份记录，停止或重置结束当前记录，下次开始另建档案。已录制内容不会被重置删除。模型输入中可能包含角色经历，过程档案同样属于本地私人数据。

在「回放」页刷新档案并打开，支持播放/暂停、下一帧、拖动进度和返回实时。进入回放会暂停当前世界；回放读取已经保存的状态，保持随机事件的实际结果，不再次请求模型。返回实时后仍保持暂停，由用户继续运行。新录制帧保存完整检查点，可从当前回放位置创建副本继续；早期录制缺少上下文时只供查看，并提示改用世界存档。档案会持续占用磁盘，当前不自动删除。

模型决策每轮最多请求3次，网络暂忙/限流可重试，格式错误会携带修正提示再询问；鉴权等明确不可重试错误不会反复立即请求。支持围栏、附加说明、多个JSON对象、常见单引号/尾逗号、中文活动名和小时/分钟格式。输出额度提高到2048～4096 token，兼容推理模型暂未输出最终内容的情况。失败后进入可见等待状态，15秒后重试（不可重试错误等待60秒），不自动替换成规则行动；世界时钟暂缓，不会因为网络等待消耗居民生命与饱食。没有绑定可用API的居民继续使用规则模式。

新配置的单次决策等待默认90秒，可在设置中调整为5～300秒；已有自定义设置保留。每次请求仍有有限超时，暂停会取消本轮应用，迟到的回答不会改写新世界。后台网络请求可能要等到自身超时才真正结束。


## 世界存档、书架和男女形象（2026-10-28）

重置顺序为：暂停并取消未完成的模型应用 → 原子保存旧世界 → 新建时间命名的独立目录和空记忆库 → 切换新世界。保存失败时中止重置并保留旧世界。新档从第1天08:00开始，居民重新选择身份。API档案与默认居民的模型绑定继续保留。

## 完整上下文存档与条目管理（2026-10-28）

手动保存创建独立时间命名的快照，保留居民属性、三级记忆及选择状态、活动剩余时间、路线、车辆、地图、进行中的对话和待处理好感请求、随机状态，以及当时的提示词、设置和模型绑定。继续所选位置会先保存当前世界，再新建副本恢复，并保持暂停。API密钥仍由本机配置管理，不写入快照；恢复模型绑定时沿用本机对应档案的密钥。正在等待的外部网络连接不能存档，恢复后从保存的决策或对话位置重新请求，不跳过对话回合。

每个新录制帧携带完整检查点。存档保存各段录制的帧数边界，后续运行不会把未来帧混入旧存档。回放可拖动并从当前帧继续；无录制的世界快照也可作为单帧回放。早期存档只能恢复当时已保存的内容，早期录制帧缺少完整上下文时禁止从帧继续。

名称与收藏独立保存，自动检查点不会覆盖它们。删除会移除该存档的世界和居民记忆；当前使用的存档需先切换后删除。历史过程记录可能被多个存档引用，删除世界条目不会删除共享录制。备份全部过程时应同时保存 `data/saves/`、`data/replays/`，密钥配置另行妥善保管。

实现要点：世界快照用于精确恢复，过程帧用于按时间查看，两者通过录制编号和帧数关联；元数据与世界状态分离，让重命名和收藏不依赖重新写入居民状态。离线检查覆盖上下文恢复、旧档兼容、帧边界、记忆隔离和取消等待时的状态保留；浏览器检查覆盖五个操作、收藏置顶、帧继续及手机布局。


## 表情、居民电脑与自主资金流动（2026-10-28）

模型可使用 `emoji` 向指定室友发送爱心、笑脸、哭脸、愤怒脸等简单表情，双方获得这次互动的普通记忆，地图角色显示短暂气泡。`computer_game` 会寻路到自己卧室的电脑前，可指定时长；原有客厅游戏继续保留。`computer` 支持 list/create/edit/read/delete，模型通过 file_id 操作自己的文字记录；只有抵达电脑、活动完成后才应用操作。目录每页20条，正文每次读取4000字，可用offset继续读取，单次创建/编辑正文最多20000字。这些限额约束单次操作，不限制记录总数，避免记录越多模型上下文越大。

电脑文档独立于自动记忆压缩，不会被记忆系统自动删除，角色可主动记录担心遗忘的经历。居民卡片展开电脑可查看全文，页面没有修改入口，也没有对外的文档写入接口；模型提示只介绍自己的电脑能力，不提用户查看能力。文本均转义显示，记录中的代码不会执行。资料随完整存档和过程帧一起保存，重置新档清空，旧档读取时默认空目录，回放也可查看当时的记录。

资金只有一个通道 `transfer`：target为收款人，amount为正金额（最多两位小数），money_from为付款人（默认自己），角色必须是付款方或收款方。系统不提供借款、赠送、抢夺或还款的方式菜单，也不自动创建债务、利息或社交惩罚；意图由角色自行决定和表述。两边余额与流水同步更新，余额不足整笔失败，不产生负余额，转移总资金守恒。用户的流水保留理由以便追溯，但模型的流水上下文排除reason；理由只通过普通记忆进入角色上下文，可能因记忆选择而遗忘，角色主动写入电脑的记录则可再次查阅。

事件区分为「游戏事件」「提示」两个可切换栏目，关键词、日期和类型筛选作用于当前栏目。新消息在地图顶部弹出，标注类别，可关闭并自动消失；同一消息不重复弹出，查询历史和只读回放不触发实时弹窗。提示继续与游戏记忆隔离。导航简化为「模型」「存档」。

验证包含电脑到达后操作、个人文档隔离、完整增删改查、完成事件中途存档防重复、电脑游戏时长、表情双方记忆、转账方向/金额/余额/守恒、理由遗忘后的上下文、存档与回放保留文档和流水，以及桌面/手机只读界面、文本转义、双栏和顶部弹窗。


小镇东北下方建筑改为饭店（R），下馆子前往饭店，费用和效果保持原数值。读取旧档时将该位置的事务所转为饭店，保留损坏格及其他世界变化。上方事务所屋顶边缘按整数像素对齐，烟囱改为落在屋面上的小型砖烟囱；指南针已移除。桌面/手机地图已检查，饭店可达且建筑主体仍不可穿行。


## 场所、技能与可编辑参数

“建设中”升级为学校，“杂货铺”改为商店。咖啡馆提供喝咖啡和阅读，饭店提供用餐与共同用餐好感收益；学校提供计算机、理学、文学、医学、经济学、烹饪课程。诊所、饭店和事务所设置基础与技能岗位，按实际工作时间支付时薪。医学支持居家行医，烹饪改善公共餐，经济学解锁电脑虚拟指数交易，其余技能关联岗位和生活收益。

点击室外建筑查看详细参数，暂停时可修改，运行和回放中只读；参数、技能、公共餐品质、持仓、市场价格和活动合同均随完整存档恢复。默认费用、课程和岗位表及结算说明见 [小镇技能与场所参数](docs/小镇技能与场所参数.md)。旧世界的施工区域自动转换为学校，不增加任何新游戏参与者。

活动数值收益按收益率乘实际时间结算，中断保留已获得的经验和工资。共同喝咖啡的默认好感增长率为每小时8，饭店共同用餐为每小时4。学费在开始学习时一次交清，不随时间重复扣费；商品和交易本金同样属于一次性付款。

档案可直接编辑名称、地址、格式、默认模型和密钥，保留档案编号及居民绑定；编辑时密钥留空沿用原值，页面不会回填原密钥。测试沿用设置中的等待时间、温度和正式决策的输出额度，优先测试档案默认模型，未设默认时使用该档案下已有居民绑定的模型，不再猜测模型名称。连接失败、等待回答超时、HTTP错误与缺少最终回答分别提示，测试结果只面向用户。

所有职业增加一级、二级岗位，二级要求更高技能、最低班次更短、时薪更高。例：一级软件工程师需计算机2级，最低120分钟、时薪90元；二级需4级，最低60分钟、时薪135元。学校提供六学科教师岗位，一级需任教学科3级，二级需5级。所有职业默认每小时积累3点对应技能经验，教师6点；学校课程参数中的工作经验率统一控制该学科所有岗位，教师始终为普通职业的两倍。相关技能每级节约工作精力2%，医学照护好感等生活收益也按技能等级增长，工资与经验按实际工作时间累计。旧档补齐新增岗位和字段，保留已修改参数和正在执行的活动合同。
